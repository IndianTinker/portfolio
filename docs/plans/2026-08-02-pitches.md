# Personalized Pitch Pages (`/for/{slug}`)

Date: 2026-08-02
Status: planned, not implemented

## What

Per-company outreach pages. Each pitch is one content file with:

- a title (e.g. "Rohit × Acme Robotics")
- a cover letter (rich text)
- an ordered, curated list of existing projects

Rendered at `/for/{slug}`. Unlisted (no links from the main site), `noindex`ed.
Created by an agent writing a `.mdoc` file + git commit + push → Vercel deploys.

## Decisions (locked)

| Decision | Choice | Why |
|---|---|---|
| Storage | New Keystatic collection `pitches/*.mdoc` | Same flow as projects/case-studies; agent writes one file |
| Route | `/for/{slug}` | Short, personal, reads well in an email |
| Privacy | Unlisted + `noindex` meta + `robots.txt` disallow | Zero friction for recipient; no server logic |
| Creation | Git commit by agent (Keystatic admin usable manually too) | Reviewable history, no auth setup |
| Projects | `fields.relationship` list → existing `projects` collection | No media duplication; reuses ProjectCard |
| Extras | "View full portfolio →" footer link | Cheap, keeps recipient in-site |

Deferred (YAGNI): expiry dates, per-pitch accent overrides, password protection.

## Implementation steps

### 1. Keystatic collection — `keystatic.config.tsx`

Add to `collections`:

```tsx
pitches: collection({
  label: 'Pitches (per-company pages)',
  slugField: 'title',
  path: 'src/content/pitches/*',
  format: { data: 'yaml', contentField: 'letter' },
  columns: ['title', 'company'],
  entryLayout: 'content',
  schema: {
    title: fields.slug({ name: { label: 'Title' } }),
    company: fields.text({ label: 'Company', validation: { isRequired: true } }),
    role: fields.text({ label: 'Role', description: 'Optional' }),
    greeting: fields.text({
      label: 'Greeting',
      description: 'e.g. "Hi Acme team —" . Optional',
    }),
    projects: fields.array(
      fields.relationship({ label: 'Project', collection: 'projects' }),
      {
        label: 'Projects to show',
        description: 'Ordered top-to-bottom',
        itemLabel: (p) => p.value ?? 'Project',
      }
    ),
    letter: richTextBody('Cover letter'),
  },
}),
```

- `letter` is the single content field → flat `src/content/pitches/{slug}.mdoc`
  files (same pattern as case studies).
- `richTextBody` already exists; reuse it.

### 2. `noindex` support — `src/layouts/Base.astro`

Add optional prop:

```astro
interface Props {
  title?: string;
  description?: string;
  noindex?: boolean;
}
```

In `<head>`:

```astro
{noindex && <meta name="robots" content="noindex, nofollow" />}
```

Default `false` — every existing page is unaffected.

### 3. `robots.txt` — `public/robots.txt` (new file)

```
User-agent: *
Disallow: /for/
```

(Belt-and-braces alongside the meta tag; harmless if a crawler ignores meta.)

### 4. Data helper — `src/lib/pitches.ts` (new file)

```ts
import { reader } from './reader';

export type PitchEntry = Awaited<
  ReturnType<typeof reader.collections.pitches.all>
>[number];

export async function getPitches() {
  return reader.collections.pitches.all();
}
```

Resolution of project relationships happens in the page (step 5), not here —
the reader returns slugs; the page reads full project entries via
`reader.collections.projects.read(slug)`.

### 5. Pitch page — `src/pages/for/[slug].astro` (new file)

Structure, reusing existing components and classes:

```astro
---
import Base from '../../layouts/Base.astro';
import ProjectCard from '../../components/ProjectCard.astro';
import Prose from '../../components/Prose.tsx';
import { reader } from '../../lib/reader';

export async function getStaticPaths() {
  const pitches = await reader.collections.pitches.all();
  return pitches.map((p) => ({ params: { slug: p.slug } }));
}

const { slug } = Astro.params;
const entry = await reader.collections.pitches.read(slug!);
if (!entry) return Astro.redirect('/');

const letter = await entry.letter();

// Resolve project slugs → full entries, preserving pitch order; skip
// dangling references rather than failing the build.
const projects = (
  await Promise.all(
    (entry.projects ?? []).map(async (s) => {
      if (!s) return null;
      const p = await reader.collections.projects.read(s);
      return p ? { slug: s, entry: p } : null;
    })
  )
).filter(Boolean);
---

<Base
  title={`${entry.title} — Rohit Gupta`}
  description={entry.role ? `${entry.role} @ ${entry.company}` : entry.company}
  noindex
>
  <article class="wrap pitch">
    <header class="pitch__head">
      <p class="eyebrow">For {entry.company}{entry.role && ` — ${entry.role}`}</p>
      <h1 class="pitch__title">{entry.title}</h1>
    </header>

    <div class="pitch__letter measure-body">
      {entry.greeting && <p>{entry.greeting}</p>}
      <Prose document={letter} />
    </div>

    <section class="pitch__projects">
      <h2 class="eyebrow rule-faint">Selected work</h2>
      {projects.map((p) => <ProjectCard project={p} />)}
    </section>

    <p class="pitch__full rule-faint">
      <a href="/" class="link-underline">View full portfolio →</a>
    </p>
  </article>
</Base>
```

Styles: copy the head/letter spacing rhythm from `projects/[slug].astro`
(`--f1` title, `--f5` eyebrow, `measure-body` = 42rem). No new CSS primitives.

Notes:
- Nav/footer stay as-is — a recipient can always reach the main site.
- No Lightbox needed (cards link out to full project pages, which have it).

### 6. Seed example — `src/content/pitches/example.mdoc`

One real pitch hand-written as a smoke-test fixture and agent template.

### 7. Agent prompt convention

Document in `CLAUDE.md` (short addition): to create a pitch, write
`src/content/pitches/{company-slug}.mdoc` with YAML frontmatter
(`title`, `company`, `role?`, `greeting?`, `projects:` list of project slugs)
+ letter body, then commit and push. Slugs must match
`src/content/projects/*.mdoc` filenames exactly.

### 8. `CLAUDE.md` updates

- Architecture tree: add `pitches/*.mdoc` collection, `src/pages/for/`,
  `src/lib/pitches.ts`.
- Content model section: one line on pitches (unlisted, noindex, relationship
  list of project slugs).

## Testing

No test framework in repo — verification is manual + build-time.

1. **Type/build gate:** `npm run build` must pass. This catches schema typos,
   bad frontmatter, and missing imports (Astro type-checks pages).
2. **Dev render:** `npm run dev`, visit `/for/example`:
   - title, company eyebrow, letter render correctly
   - project cards appear **in the order listed** in the pitch file
   - card links go to `/projects/{slug}` and those pages work
   - "View full portfolio →" goes to `/`
3. **noindex:** view source on `/for/example` →
   `<meta name="robots" content="noindex, nofollow">` present; `/robots.txt`
   serves the `Disallow: /for/` rule.
4. **Unlisted:** grep the built `dist/` for `/for/` — should appear only in
   pitch pages and `robots.txt`, never in index/nav/footer/sitemap.
5. **Dangling reference:** temporarily add a bogus slug to the example pitch's
   `projects` list → build still passes, card silently omitted. Revert.
6. **Keystatic admin:** open `/keystatic`, confirm "Pitches" collection
   appears and the example entry loads with the relationship pickers working.
7. **Unknown slug:** `/for/does-not-exist` → redirect to `/` (no 500).

## Out of scope

- Expiry / revocation of links (delete the file + push to revoke — good enough).
- Analytics on pitch views.
- Per-pitch theming.
- Password protection.
